## Executive Summary

**construct-arneson v3.2** adds the **freeside-characters adapter** -- bidirectional read/write between Arneson's voice-character schema and freeside's persona.md format. This eliminates the two-source-of-truth problem: Arneson workshops the voice, the persona.md stays the single file, both the human-readable reference body and the bot-readable system prompt template stay in sync.

> **Source:** 0xHoneyJar/construct-arneson#7

---

## Problem Statement

Arneson speaks YAML. The freeside-characters bot speaks persona.md with a specific loader contract. Today, workshopping a character means either maintaining two files that drift, or skipping Arneson entirely. The adapter makes `/voice` read and write persona.md natively.

## Functional Requirements

#### FR-A1: Adapter Specification
**Priority:** Must Have
**Description:** `domains/character-voice/adapters/freeside.yaml` -- machine-readable bidirectional mapping between voice-character schema fields and persona.md sections. Declares ingest rules (persona.md -> schema) and emit rules (schema -> persona.md).

**Acceptance Criteria:**
- [ ] Adapter spec exists with ingest + emit mappings for all voice-character fields
- [ ] Covers the persona.md section mapping from issue #7 (OG voice anchor, battle whispers, voice discipline lock, cadence, decline patterns, yield patterns, modes, world presence, system prompt template sections)
- [ ] Declares the freeside loader contract (`## System prompt template` -> 4-backtick block, `INPUT PAYLOAD` marker, `@FRAGMENT` markers)

#### FR-A2: `/voice` Reads persona.md
**Priority:** Must Have
**Description:** When invoked with `--source <path-to-persona.md>`, `/voice` detects the format (markdown vs YAML), loads via the adapter, extracts voice-character state, and workshops as normal.

**Acceptance Criteria:**
- [ ] `/voice` accepts `--source` flag pointing to a persona.md file
- [ ] Format detection works (markdown with frontmatter vs YAML)
- [ ] Voice-character fields are correctly extracted from persona.md sections
- [ ] Workshop session runs normally against the extracted state

#### FR-A3: `/voice` Writes Back to persona.md
**Priority:** Must Have
**Description:** On session close, `/voice` persists workshop changes back to the source persona.md. Updates BOTH the reference body sections AND the system prompt template block atomically. When a decline pattern is added, it appears in both the `### decline patterns` section and the system prompt's `DON'T` section.

**Acceptance Criteria:**
- [ ] Workshop changes write back to the source persona.md
- [ ] Both layers updated atomically (reference body + system prompt template)
- [ ] Decline pattern edits appear in both layers
- [ ] Voice anchor updates propagate to `VOICE CANON` section in system prompt
- [ ] Anti-pattern additions propagate to `DON'T` section in system prompt
- [ ] Canon boundary changes propagate to `CANON BOUNDARY` section in system prompt

#### FR-A4: `/distill` Emits persona.md Edit Recommendations
**Priority:** Should Have
**Description:** When the consumer format is `freeside-characters`, `/distill` produces a digest that maps workshop findings to specific persona.md edits with file paths and section references.

**Acceptance Criteria:**
- [ ] Digest includes edit recommendations (which section, what to change, why)
- [ ] Recommendations reference specific persona.md sections by name
- [ ] Voice drift findings map to `DON'T` section edits
- [ ] Canon matches map to exemplar capture recommendations

#### FR-A5: Consumer Declaration
**Priority:** Must Have
**Description:** `construct.yaml` declares `freeside-characters` as a known consumer under `domains.character-voice.consumers`.

**Acceptance Criteria:**
- [ ] `construct.yaml` has consumer entry with adapter path, repo, persona path pattern

## Scope

**In scope:** Adapter spec, `/voice` read/write for persona.md, `/distill` edit recommendations, construct.yaml consumer declaration
**Out of scope:** Automated git commit/push to freeside-characters repo, persona-engine loader changes, multi-file persona formats

---

## Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| persona.md format changes upstream | Medium | Adapter spec is versioned. Pin to known loader contract. |
| Two-layer sync logic is fragile | High | Atomic write: compute full file content before writing. Never partial update. |
| Section parsing is heuristic (markdown headings) | Medium | Define exact heading patterns in adapter spec. Test against all 5 KIZUNA personas. |
